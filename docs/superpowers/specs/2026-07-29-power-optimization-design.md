# StickC 续航优化设计

## 目标

降低新增 BLE 标题同步对原版 M5StickC 续航的影响，并加强屏幕关闭后的省电状态，同时保持 Codex Micro HID 连接和按键行为稳定。

## 已确认根因

当前实现存在三项新增开销：

1. HID 连接成功后仍持续使用 NimBLE 默认的快速可连接广播。
2. 桌面服务在标题不变时仍每 30 秒建立 BLE 连接并重复同步。
3. 固件收到每次同步后都会将六个标题重新写入 NVS。

原有固件还会在屏幕关闭后以 240 MHz 和约 8 ms 的循环周期继续运行。它不进入轻睡眠或深睡眠，这是为了避免 Codex HID 断链，但仍有安全的降频空间。

## 方案

### BLE 广播

- 设备未建立任何连接时使用快速广播，保证首次配对和断线恢复速度。
- 建立第一条连接后继续提供标题服务，但把广播间隔调整为约 1 秒。
- 最后一条连接断开后恢复快速广播。
- 保留 +9 dBm 发射功率和现有安全配置，避免同时改变距离和兼容性。

广告模式由独立、可原生测试的状态函数决定。连接回调只负责把连接数量变化传给状态函数并应用对应间隔。

### 标题同步

- 标题分配发生变化时仍在下一次 1 秒轮询中立即同步。
- 标题不变时的恢复刷新从 30 秒改为 5 分钟。
- USB 优先、BLE 回退的传输顺序保持不变。
- 日志继续只记录已分配标题数量。

五分钟刷新用于设备重启后的标题恢复。最坏情况下，设备重启后会显示 `AGENT N` 最多五分钟；任何标题分配变化都会立即触发同步。

### NVS 去重

- 固件仍然在收到第一份有效标题包后切换到标题 UI。
- 仅当某个槽位的持久化标题值发生变化时才调用 `putString`。
- 如果六个标题都未变化，不产生 NVS 写入。
- 即使标题未变化，当前启动会话仍接受该包并切换到标题 UI，以支持重启恢复。

### 屏幕关闭后的省电状态

- Active 和 Dim 状态保持 240 MHz，不改变操作响应。
- 进入 Off 状态时：
  - 关闭并休眠显示屏。
  - 调用 M5Unified 的 IMU 硬件休眠。
  - 将 ESP32 CPU 降至 80 MHz。
  - 将主循环等待时间从 8 ms 增加到 50 ms。
- 从 Off 唤醒时：
  - 先恢复 240 MHz。
  - 通过内部 I2C 和当前板型重新初始化 IMU。
  - 唤醒显示屏并恢复原有亮度。
- BLE、串口标题接收、按键扫描、电池采样和 VBUS 恢复逻辑在 Off 状态继续运行。
- 不启用 light sleep 或 deep sleep。

## 状态与接口边界

新增两个无硬件依赖的小型策略模块：

- `BleAdvertisingPolicy.h`：根据连接数量返回快速或低功耗广告间隔。
- `PowerModePolicy.h`：根据屏幕状态返回 CPU 频率和主循环等待时间。

标题持久化去重保持在 `main_stickc.cpp`，通过可测试的纯函数判断新旧标题是否相同。Python 服务的刷新策略继续由 `should_sync` 测试覆盖。

## 测试

1. Python 测试确认标题变化立即同步，标题不变时五分钟后刷新。
2. C++ 原生测试确认零连接使用快速广播，有连接使用约一秒广播。
3. C++ 原生测试确认 Active、Dim 和 Off 对应正确的 CPU 频率与循环等待。
4. C++ 原生测试确认相同标题不需要持久化，但仍可激活标题 UI。
5. 运行全部 Python 测试、全部 C++ 原生测试和 PlatformIO 固件构建。

## 不在本次范围

- 不修改电池容量曲线或百分比估算器。
- 不启用自动轻睡眠、深睡眠或断开 BLE 的超低功耗模式。
- 不改变页面布局、按键映射、HID 报告或标题协议。
